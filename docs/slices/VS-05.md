# VS-05 — POC Ingestion Pipeline

Status: Approved for implementation

## Objective

Turn the certified VS-02/VS-04 discovery primitives into a repeatable Malta POC ingestion pipeline that can acquire only policy-approved sources, normalize them deterministically, classify freshness, deduplicate recurring discoveries, persist provenance in PostgreSQL and return an explainable ranked feed.

## Scope

### In scope

- POC/research source selection from the certified Malta source catalog.
- Static acquisition through Scrapy.
- Browser fallback through `scrapy-playwright` only for catalog entries explicitly marked `browser`.
- SourcePolicy scope/path enforcement before acquisition.
- Robots enforcement and fixed-source acquisition constraints.
- Deterministic adapter selection and normalization before any AI step.
- Freshness classification using the existing freshness rules.
- Stable discovery fingerprints and idempotent persistence.
- PostgreSQL ingestion-run metrics and per-source results.
- Deterministic ranking of non-expired discoveries.
- Tests for policy bypass prevention, dedupe/idempotency, stale expiry behavior, acquisition-mode routing and PostgreSQL persistence.

### Out of scope

- Production source enablement.
- Scheduled/continuous crawling.
- New source-policy permissions beyond the certified VS-04 matrix.
- Proxy rotation, stealth, CAPTCHA bypass or anti-bot bypass.
- Merchant onboarding.
- User-facing mobile feed UI.
- AI/LLM extraction.
- Meta Ad Library credentials or production activation.

## Requirements covered

- `REQ-SRC-001` — explicit source access/policy status.
- `REQ-SRC-002` — no intentional bypass of access controls or restrictions.
- `REQ-SRC-003` — prohibited sources remain API/partner/deep-link/user-share only.
- `REQ-SRC-004` — source reliability and last-success metadata are tracked.
- `REQ-DIS-001` — normalize source signals into the universal Discovery model.
- `REQ-DIS-005` — deduplicate equivalent discoveries.
- `REQ-FRS-001` — explicit freshness state.
- `REQ-FRS-002` — expired discoveries are not ranked as active.
- `REQ-FRS-003` — discovered/last-seen verification timestamps are persisted.
- `REQ-FRS-004` — stale/expired rate is measurable.
- `REQ-FRS-005` — valid-when-opened POC gate is measurable.
- `REQ-PER-001` — deterministic ranking uses freshness/value/novelty/urgency and accepts location/interest context.
- `REQ-PER-004` — ranker returns a relevance-ordered subset rather than exhaustive inventory.

## Acceptance criteria

1. A source outside the approved catalog, policy scope or approved path cannot be acquired.
2. `partner_only`, `user_share_only` and `deny` sources cannot enter automated POC acquisition.
3. Browser acquisition is used only for entries configured as `browser`; static sources remain static-first.
4. The same normalized discovery observed repeatedly produces one canonical persisted discovery row with incremented seen metadata rather than duplicates.
5. Explicitly expired discoveries persist as evidence but are excluded from active ranking output.
6. Source observations remain append-only and source-state promotion remains monotonic.
7. Every ingestion run records start/end state, source counts, candidate counts, inserted/updated/duplicate/expired counts and failure reasons without storing raw page content.
8. PostgreSQL migration/tests pass against PostgreSQL 16 + PostGIS + pgvector.
9. Existing kernel, Meta and VS-04 source-policy regressions remain green.
10. Full PES preflight passes.

## Safety invariants

- POC scope only; production policy and production-enable gates remain separate.
- No source is enabled by technical capability alone.
- Raw page bodies are transient unless a later policy explicitly allows storage.
- Persisted evidence contains normalized facts/provenance, not copied promotional creative.
- Network acquisition treats all URLs/content as untrusted input.
- No scheduled job is enabled by this slice.

## POC metrics

- useful discovery candidates/day
- unique persisted discoveries/day
- duplicate rate after processing
- expired/stale rate
- source success/failure/blocked rate
- static vs browser acquisition rate
- candidates per source and source class
- source last-success time
- ranked active discovery count

## Rollback

VS-05 is additive. Rollback disables the POC runner and leaves append-only observations/discovery evidence intact. Migration rollback is not destructive; production execution of migrations remains a separate release concern.
