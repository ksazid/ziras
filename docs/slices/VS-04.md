# VS-04 — Malta Production Source Adapter Pack

## Goal

Convert the multi-vendor OSS qualification work into a governed Malta source pack that can measure real discovery density/freshness without turning Ziras into an unrestricted scraper.

## Approved scope

1. Add a declarative source catalog for Malta vendor/source families.
2. Add policy scope levels: `research`, `poc`, `production`.
3. Add approved-path, request-rate, attribution and content-retention controls to `SourcePolicy`.
4. Add deterministic public-web promotion/event normalization before AI.
5. Add a low-rate robots-aware live smoke runner for fixed approved URLs.
6. Track static/browser/API/partner source modes explicitly.
7. Encode current vendor decisions so blocked sources cannot accidentally run.
8. Keep production enablement separate from research/POC collection.
9. Add PostgreSQL migration coverage for the new policy controls.
10. Extend CI with source-pack unit/integration/PES gates.

## Source-policy decisions in this slice

### POC-scoped candidates
- VisitMalta events — factual event metadata only; browser fallback; production re-review required.
- Eden Cinemas — factual promotions/events only; static; production re-review required.
- Homemate special offers — factual offer metadata only; static; production re-review required.

### Research-only candidates
- Eurospin Malta promotions.
- Lidl Malta offer pages.

### Explicitly blocked / partner-only
- McDonald's Malta — terms explicitly prohibit unauthorized automated extraction.
- Pizza Hut Malta — website material limited to personal/non-commercial reproduction.
- Franks Malta — site provided solely for personal use; commercial use prohibited.
- Wolt Malta — partner/API/affiliate route only.
- Zara Malta — partner/API/affiliate or user-share route only.
- Cloudigo Malta — licensed/partner inventory only.
- SCAN, SPAR, TicketLine and ShowsHappening — remain disabled until permission/reuse basis is established.

## Runtime invariants

- Unknown source => denied.
- Requested environment cannot exceed the policy scope.
- Requested URL path must be inside the approved path set.
- `robots.txt` is mandatory whenever the source policy says so.
- Fixed allowlisted URLs only in the live smoke runner.
- No login, CAPTCHA bypass, proxy rotation, stealth or anti-bot bypass.
- Cross-host redirects are rejected by the smoke runner.
- Private/link-local/loopback destinations are rejected.
- Page bodies are capped and not persisted by default.
- Observations/discoveries retain source URL and content hash.
- Production source access still requires a production-scope policy plus later production-enable approval.

## Acceptance criteria

- Existing kernel + Meta tests stay green.
- New source catalog has unique source keys and at least 10 vendor/source entries.
- Explicit deny/partner sources cannot be treated as public-web allow.
- Research-only sources cannot run under `poc` or `production` scope.
- Approved path prefixes reject unrelated paths.
- Promotion fixtures extract original/current price + expiry without AI.
- Event fixtures extract dated events without AI.
- PostgreSQL schema records policy scope, allowed paths, rate cap, attribution and retention controls.
- Live smoke runner cannot access an unapproved source/path.
- Full PES preflight stays green.

## Out of scope

- Production source enablement.
- Automatic browser crawling in CI.
- Vendor login/account/session crawling.
- Creative/image mirroring.
- Merchant portal.
- Unapproved APIs/feeds.
- Circumventing source controls.
