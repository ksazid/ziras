# VS-03 — Meta Ad Library Source Adapter

## Goal

Add Facebook/Instagram advertising as an official-API source family for the Ziras discovery engine without scraping Meta properties and without enabling production credentials.

## Approved scope

1. Add a `MetaAdLibraryClient` using the official Meta Ad Library / Graph API endpoint.
2. Support Malta-first `MT` reached-country queries.
3. Support explicit `FACEBOOK` and `INSTAGRAM` publisher-platform filters.
4. Request useful ad evidence fields (advertiser Page, creative text, dates, snapshot URL, publisher platforms and EU-specific fields when Meta returns them).
5. Normalize Meta ad results into `SourceObservation` records; do not classify every ad as a discovery/deal.
6. Track runtime and external enablement dependencies through a fail-closed readiness model.
7. Keep the capability disabled by default.
8. Keep access tokens out of URLs, persisted evidence and repository configuration.
9. Preserve source-policy approval as a separate production gate.
10. Add deterministic tests and an operator setup/runbook.

## Enablement dependencies tracked by the engine

- operator Facebook account / Meta onboarding identity-location confirmation
- Meta for Developers account ready
- Meta Platform Policy accepted
- Meta developer app ID configured
- Ad Library API access confirmed
- access token present in secret storage
- supported Graph API version pinned
- Ziras `meta_ad_library` SourcePolicy approved
- reached countries configured
- publisher platforms configured
- explicit feature enable flag

## Acceptance criteria

- Adapter is `disabled` by default.
- Partial configuration returns `missing_dependencies` and refuses requests.
- Fully configured test state returns `ready`.
- Default Malta configuration selects `MT` + both `FACEBOOK` and `INSTAGRAM`.
- Queries use `/ads_archive` and official API parameters.
- Access token is supplied through the Authorization header and never included in the request URL.
- Snapshot URLs have `access_token` removed before persistence.
- Meta paging stores only the cursor rather than the raw `paging.next` URL.
- Meta API errors fail explicitly.
- No live Meta credential is required in CI.
- Existing kernel, PostgreSQL integration and PES preflight gates remain green.

## Explicitly out of scope

- Facebook/Instagram page scraping
- CAPTCHA/anti-bot bypass
- production Meta token configuration
- production source-policy approval
- scheduled production collection
- creative asset downloading/storage
- automatic assumption that an ad is a discount/deal
- Meta Ads Manager/private advertiser account data

## Product-owner approval

Scope and implementation approved in conversation on 2026-08-31. Production source-policy approval and production enablement remain separate gates.
