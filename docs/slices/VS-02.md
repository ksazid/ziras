# VS-02 — Discovery Kernel Foundation

## Goal

Implement the first production-quality Ziras discovery-kernel foundation from approved ADR-001 without enabling production crawling or shipping mobile UI.

## Requirements

- `REQ-DK-001` — Define stable domain contracts for `SourcePolicy`, `SourceObservation`, `CanonicalEntity`, `Discovery`, `Evidence`, `Freshness`, `Interest`, `Interaction` and `Watch`.
- `REQ-DK-002` — Implement PostgreSQL schema/migrations for observations, entities, discoveries, evidence/provenance, source policies and freshness state, with PostGIS and pgvector extensions.
- `REQ-DK-003` — Preserve observation provenance and enforce monotonic observation ordering so an older observation cannot overwrite a newer one.
- `REQ-DK-004` — Implement source-policy decisions that fail closed: `allow`, `partner_only`, `user_share_only`, `deny`, each with reason and policy evidence.
- `REQ-DK-005` — Implement narrow ports for `BrowserRenderer`, `Geocoder`, `JobQueue` and `Ranker`; domain code must not depend on Photon, Huey or Playwright directly.
- `REQ-DK-006` — Implement deterministic extraction primitives for structured metadata, price and date normalization before any AI fallback.
- `REQ-DK-007` — Implement collision-resistant entity candidate scoring using external IDs, normalized name, category, geography/address and source evidence; name similarity alone must never merge entities.
- `REQ-DK-008` — Implement freshness classification with explicit `verified_live`, `likely_live`, `unverified`, `expired` states and guarantee that explicitly expired discoveries are never active.
- `REQ-DK-009` — Implement one generic structured-HTML adapter plus fixture-based adapters/tests; no vendor-specific production crawling is enabled in this slice.
- `REQ-DK-010` — Add deterministic tests for source-policy denial, stale observation ordering, expiry, entity collision, extraction and adapter isolation.

## Architecture constraints

ADR-001 and DEC-01 are authoritative.

- Python 3.12 modular monolith.
- PostgreSQL 16 + PostGIS + pgvector.
- Scrapy 2.18.0 static-first; scrapy-playwright 0.0.48 is browser fallback only.
- Extruct, Trafilatura, price-parser and Dateparser before AI.
- PostgresHuey behind `JobQueue`.
- Photon behind `Geocoder`.
- No Redis, separate vector DB, Elasticsearch/OpenSearch, Crawl4AI, Crawlee or Firecrawl in MVP core.
- No stealth, proxy rotation, CAPTCHA bypass or anti-bot bypass.

## Allowed implementation

- `services/discovery/**`
- discovery-specific CI/test workflow
- `docs/slices/VS-02.md`
- `product/TRD.md` only where needed to record the concrete schema/module baseline
- `delivery/current-slice.json`

## Explicitly out of scope

- Production source credentials or partner APIs.
- Bolt scraping or any source disallowed by policy.
- Vendor-specific production collectors.
- AI/LLM extraction provider implementation.
- User authentication/authorization.
- Mobile UI or onboarding implementation.
- Production deployment, release or production enablement.

## Acceptance criteria

1. Domain contracts do not import infrastructure adapters.
2. Schema creates PostGIS and pgvector-backed primitives and records source/provenance timestamps.
3. SourcePolicy fails closed for unknown/unapproved sources.
4. Explicit expiry always wins over relevance/value ranking.
5. Smart Supermarket and Smart Mobility do not auto-merge on name similarity.
6. Generic structured HTML fixture produces a normalized observation/discovery without AI.
7. Unit/integration tests run in CI and pass deterministically.
8. No live production crawl is enabled by this slice.
