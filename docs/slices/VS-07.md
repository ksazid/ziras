# VS-07 — 14-Day POC Metrics Validation

Status: Implementing

## Objective

Run the formal Malta discovery-engine POC measurement window against the approved PRD gates without enabling production source access, automatic scheduling, merchant onboarding, or release.

## Validation window

- Duration: 14 consecutive calendar days.
- Start: first accepted governed daily measurement run after VS-07 measurement tooling is certified.
- End: after 14 accepted daily measurement records exist.
- Geography: Birkirkara, Sliema, Gżira, St Julian’s, Valletta.
- Source policy: existing VS-04 baseline plus certified VS-06 POC-only extensions.
- Production source access: OFF.
- Scheduler: OFF; daily runs remain explicitly/manual triggered unless separately approved.

## PRD gates

| ID | Gate | Pass threshold |
| --- | --- | --- |
| POC-01 | Useful discoveries/day | >= 50/day |
| POC-02 | Valid when opened | >= 90% |
| POC-03 | Stale/expired recommendations | < 5% |
| POC-04 | Duplicates after processing | < 5% |
| POC-05 | Independent source types | >= 5 |
| POC-06 | Relevant to selected interests | >= 70% |
| POC-07 | Merchant onboarding | 0 required |

## Measurement contract

Each accepted daily record must bind to:

- UTC/Malta measurement date;
- exact repository SHA;
- exact GitHub Actions run ID;
- source-level acquisition status and candidate count;
- total candidates, ranked/surfaced discoveries and useful-discovery count;
- valid-open sample count and valid-open count;
- stale/expired surfaced count;
- duplicate count after processing;
- distinct approved source classes contributing candidates;
- relevance sample count and relevant count;
- merchant-onboarding count;
- pass/fail result for every measurable daily gate;
- integrity status so missing/partial evidence fails closed.

## Aggregation rules

- `useful_discoveries_per_day` is evaluated for every accepted day and across the 14-day mean; no fabricated interpolation for missing days.
- validity rate = valid opens / sampled opens.
- stale rate = stale or expired surfaced recommendations / surfaced recommendations checked.
- duplicate rate = duplicates after processing / processed discoveries.
- source-type coverage is the count of independent approved source classes that produced usable discoveries during the window.
- relevance rate = discoveries judged relevant / relevance sample.
- merchant onboarding must remain exactly zero.
- A day with incomplete required evidence is `invalid` and does not silently count as a pass.

## Acceptance criteria

VS-07 can pass only when:

1. fourteen accepted daily records exist;
2. each record is reproducibly bound to immutable run/SHA evidence;
3. all PRD thresholds are computed from stored evidence;
4. no source-policy restriction was relaxed;
5. production source access remained OFF;
6. scheduler remained OFF unless separately approved;
7. PES, Discovery Kernel and PostgreSQL/PostGIS/pgvector gates remain green;
8. the final report states PASS or FAIL per gate and does not infer missing observations.
