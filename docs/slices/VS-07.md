## Measurement contract

Each accepted daily record must bind to:

- measurement date;
- exact measured repository SHA;
- exact GitHub Actions run ID;
- source-level acquisition status, `source_key`, `source_class` and candidate count;
- total candidates and ranked discoveries;
- audited useful-discovery count;
- audited valid-open sample/count;
- stale/expired count;
- duplicate count after processing;
- distinct approved `source_class` values contributing candidates;
- audited relevance sample/count against an explicit interest profile;
- merchant-onboarding count;
- PASS/FAIL result for every gate;
- integrity status so missing/partial evidence fails closed.

### Machine evidence

Machine-derived fields include candidate/ranked counts, duplicate/stale counts, contributing source classes and `merchant_onboarding_count=0`. The merchant value is machine evidence because the POC acquisition pipeline has no merchant-onboarding dependency.

### Audit evidence

Every ingestion artifact now includes `poc-audit-template.json`:

- all serialized ranked discoveries are presented for useful/not-useful review;
- up to 30 discoveries are deterministically sampled round-robin by source class then source key for valid-open and relevance review;
- an explicit `interest_profile` is required before relevance can be judged;
- all required labels must be true/false before the audit can be converted to measurement counts;
- missing labels or interest profile fail closed; no audit result is fabricated.

## Aggregation rules

- A complete failing day remains evidence and cannot be discarded to cherry-pick a passing window.
- An incomplete/partial day is invalid and cannot silently count as a pass.
- duplicate rate = duplicates after processing / processed candidates.
- stale rate = stale or expired surfaced recommendations / processed candidates.
- source-type coverage = distinct approved `source_class` values with usable discoveries; source keys are not counted as independent types.
- validity rate = valid opens / sampled opens.
- relevance rate = relevant discoveries / relevance sample.
- merchant onboarding must remain exactly zero.
- The formal result cannot pass until fourteen complete accepted daily records exist.

## AX Day 1 extraction hardening

Day 1 proved that broad page extraction could over-count related-site offers:

- AX dining produced 45 duplicates across four detail URLs;
- AX wellness produced 24 duplicates across two broad pages;
- total AX duplicates = all 69 duplicates in the Day 1 run;
- broad wellness pages also emitted CTA/FAQ/navigation noise.

The corrective rule is:

- direct `/offers/.../<slug>/` and `/special-offers/.../<slug>/` pages use the page H1 as the authoritative discovery boundary;
- site-wide related-offer rails and repeated JSON-LD are not treated as additional discoveries on a detail page;
- generic/action/FAQ/pagination headings are rejected;
- AX wellness is narrowed to the current direct Day by the Pool offer page rather than broad gift-voucher/general wellness pages.
